Spec notes — the parts a screenshot cannot express. One save model: instant apply with Undo. Every change applies immediately and raises a toast carrying Undo. There is no Save button, no dirty state, no confirm-on-close — there is nothing unsaved to lose. Credentials are the single exception: an API key commits on blur, not per keystroke. This replaces three simultaneous save models and three silent-discard exits (Close, ✕, Cancel), and it removes the bug where saving in one card overwrites text still being typed in another. Eight sections, grouped by the object being configured rather than by where a setting happened to fit. General sits alone above two clusters: Setup (the machine and its credentials — Box, Accounts, Models) and Agent (what it does and what it can reach — Sessions, Files, Extensions, Voice). It is a real dialog. role="dialog", a focus trap, Esc to close, focus restored to the opener, role="tablist" on the rail so arrow keys move between sections, and every input associated with its label. None of that is true today. Alignment: the rail is fixed-width and left-aligned; each section is a single column of cards, left-aligned within the pane — not centred, not full-bleed. Card padding is 12px vertical / 16px horizontal; header → body 12px; body → button row 16px. Emphasis: nothing on this screen is loud. The only accent-coloured elements are the selected rail item and an active control. Destructive actions are confined to a Danger zone card at the end of a section and are outlined, never filled. What grows: the section pane scrolls; the rail never does. The row tags are part of the spec: an untagged row exists today, config only means the config key exists with no screen, and new means it does not exist yet — so an implementer can tell a restyle from a build.
