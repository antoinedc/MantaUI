What's wrong today

  • The modal is the narrowest surface in the app (560px) holding its widest content. Lists, numbers and code wrap early, and the header sentence competes with the card's own title.
  • It's a dead end: no previous/next run and no way to reply. "See full transcript" swaps to a different screen with a different header, so the two feel unrelated.

Patterns other tools use for "a run and its result"

  • GitHub Actions / Vercel deployments: a run is a page. "Summary" (the outcome) is the default tab and "Logs" or "Jobs" sits beside it. The URL is the run, and prev/next or re-run sit in the header. → A
  • Linear Inbox, Mail, Sentry issues: a list on the left and a reading pane on the right. You triage many items without opening or closing anything. → B
  • Notion / Linear peek, Figma comments: a wide side sheet over the list keeps your place. → C
  • ChatGPT scheduled tasks drop each result into its own conversation, which is what our transcript does today. It's the thing users found awkward: the answer is buried at the end of the steps that produced it.

A · Report page with a Transcript tab — recommended

  • Clicking a run opens a full page in the same place the transcript lives now. Its header has a Report | Transcript switch, ‹ › to move between runs, and × back to Routines.
  • The white card, footer included, is shown at reading width (the transcript's measure), with nothing else competing. Follow up stays in its footer. Under it are two collapsed lines: "How it got there" (jumps to the Transcript tab) and "Memory updated".
  • The Transcript tab is today's run view, with the same header. The report is no longer repeated at the end; there's a one-line "Back to the report". Its composer offers follow-up directly, and sending moves the run into the sidebar (same as Follow up).
  • A run with nothing to report (running, waiting on you) opens on the Transcript tab. Notifications open on Report.
  • Cost: smallest change. It reuses the run route, run bar and ChatPanel; the modal is deleted and the switch is a SegmentedControl in the header.

B · Inbox split on the routine page

  • The routine's run list becomes the left column, and the selected run's report fills the right. You can read many runs without opening anything, and the arrow keys move through them.
  • Best for daily routines you skim. It needs a second design for the cross-routine "New findings" list (the same split on the Routines page), and the transcript still opens as its own screen.
  • Cost: medium. It replaces the routine page's two-column layout, and the side column (memory, instructions) moves to a tab or drawer.

C · Wide side sheet

  • A 640px sheet slides over the right of the page with the full card, ‹ › and the footer actions. The list behind stays visible and dimmed.
  • The least disruptive change from today (it's the modal, made tall and wide and anchored to the edge). But it's still an overlay: the transcript remains a separate screen, and on a narrow window the sheet covers almost everything.
  • Cost: small. It needs a new sheet surface (no existing primitive), and the transcript doesn't change.
