Spec notes — the parts a screenshot cannot express. Everything in the modal is left-aligned to the modal's own left edge; nothing is centred. The modal itself is centred on the dimmed backdrop (like every dialog). The path field is full-modal-width with an accent border + pinned focus ring (4px of --accent-bg), so it is the control the eye lands on; the primary Select folder button (filled accent) is the single loudest action, right-aligned in the footer with Cancel (ghost) beside it. The breadcrumbs sit directly under the path field, left-aligned, one level up per chevron; the current crumb is the only one at full text weight. The folder list grows vertically — it is the only scroll region, clamped by the modal's max-height — and node_modules + dot-folders render dimmed, not hidden, so nothing becomes unreachable (shown in the home state; the captured ~/projects state has no dimmed rows, only the dimmed ..). The design's Go button is part of the discovery affordance the current app ships without (a divergence, recorded in conformance.md).

Off-grid values in the design — reported, not transcribed. The source uses a 34px path-field height and a 9px list-row vertical padding, both off the app's 4px grid; the mockup re-grades them to 36px and 8px. The list max-height: 222px is likewise off-grid (used only to fit the spec's 520px frame); the mockup uses 208px here and the real size is the modal max-height's concern, not a fixed list height. The 12.5px breadcrumb/row font is off the app's text scale and reads as 13px here. A real implementation should keep its own on-grid values and resolve these against the acceptance rules.
