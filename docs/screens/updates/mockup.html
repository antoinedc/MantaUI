.mk-bar-one — exactly ONE target available

Claude Code has an update available

Singular copy names the ONE thing. Never "1 update available" — that is a count nobody needed. The phrasing "<label> has an update available" is used for ALL six targets so no label needs an article or special-casing. Version numbers are deliberately absent from the bar: they belong in Settings, and they push the names out of a one-line bar.

.mk-bar-many — 2 or more targets available

3 updates available · Manta UI, the box, Claude Code

Names are listed in the FIXED display order (Manta UI, the box, opencode, then CLIs alphabetically) — never in completion or discovery order, which would make the same state render differently twice. Past three names the tail collapses: "4 updates available · Manta UI, the box, opencode +1 more".

.mk-bar-step — running, determinate

Updating Claude Code (2/7)

.mk-bar-busy — running, indeterminate (restart / desktop install)

Restarting the box…

While busy the bar shows NO action and NO dismiss — today's behaviour, unchanged. One label at a time; the orchestrator owns which.

.mk-bar-required — mandatory, non-dismissible

Manta UI must be updated to keep working with this box

Same bar, no ✕. Mandatory is a FLAG on the aggregate, not a separate banner — that is what removes the version-skew bar as its own case.

.mk-bar-failed — an update failed (NEW tone)

Update failed: the download could not be verified

The ONLY new visual token pairing in this spec: --danger-rgb at the same 0.10 / 0.30 / 0.20 alphas the accent tone already uses. A failure rendered in the accent tint is the bug this fixes.

One row shape, six instances. A target the box does NOT have installed produces no row at all — the list is built from what exists, never from a hardcoded roster. "Couldn't check" is --danger and is NEVER rendered as "Up to date": an unanswerable check is not a clean bill of health. A target whose upgrade command we cannot determine gets the muted dot and a link, never a button that would run the wrong thing.
