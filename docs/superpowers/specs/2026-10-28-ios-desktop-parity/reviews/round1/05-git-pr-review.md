# WS05 review — round1

1. **BLOCKING — §6.2, §9, §11.1: Inbox creation contradicts the binding draft contract.** The spec creates a worktree before opening the create flow, requires immediate creation without further prompts, and adds `forgeIssue` to `NewSessionDraft`. Master D2 instead fixes that type to `cwd/text/attachments/worktreeBranch/linkedIssueURL` and explicitly requires a Create confirmation. Evidence: `00-master.md:195-211`; the actual worktree operation mutates git immediately (`src/server/local.mjs:295-324`); issue linking is consumed separately by the server (`src/server/rpc.mjs:1011-1030`). **Fix:** hand `MantaNavigator.startNewSession` the existing repository cwd, requested `worktreeBranch`, seed and `linkedIssueURL`; let WS04 create the worktree only after confirmation. Specify how WS04 derives/passes the issue reference from the URL using its owned API, or obtain an explicit master-contract amendment. Remove the automatic-creation fallback and update acceptance tests to include cancellation without mutation.

2. **BLOCKING — §4.2–4.3, §7, §9, §11.2: Device-flow ownership and public name conflict with D5.** WS05 defines/provides `GitConnectGitHubSheet` and asks WS04 to write WS05's `Git*` files. Master D5 instead assigns the reusable `GitHubDeviceSignIn` view in `CloneFromGitHub*` to WS04 in wave A. Evidence: `00-master.md:220-222`, versus this spec's file inventory and §11.2 (`05-git-pr-review.md:777,857-858,887-892`). **Fix:** make §4 a behavioral contract for WS04's `GitHubDeviceSignIn`, use that exact public component in both inbox and header, and remove duplicate device-store/model/API ownership from WS05. Pin where shared wire methods live so wave C consumes rather than redeclares them.

3. **BLOCKING — §2.3/§8.1: Read-only background chats still expose review-to-composer writes.** `readOnly` gates the checks action, but the branch sheet always passes a non-nil `onSendToAgent` callback to `ReviewScreen`; that screen renders Send actions whenever the callback exists. This bypasses the explicitly excluded ability to type into a subagent. Evidence: `00-master.md:14-15`; `05-git-pr-review.md:254-255,367-369,558-561,801-803`. **Fix:** propagate the writable-chat condition to the branch sheet and pass nil to review when read-only, with a second guard at the composer insertion callback. Add acceptance coverage for both line-comment and saved-draft Send actions opened from a background job.

4. **BLOCKING — §2.3: Merge confirmation is not tied to a stable PR snapshot.** `merge(cwd:)` reads `state.pr!.headSha` when confirmation completes, while the same store polls every five seconds. A poll while the dialog is open can replace the PR/revision, so the request need not target what the user saw when opening the confirmation; a poll clearing the PR can also crash the force unwrap. Evidence: `05-git-pr-review.md:185-188,200-202,248-251`; the server trusts the supplied number/SHA (`src/server/forge/index.mjs:1218-1223`); desktop explicitly captures a guarded PR before awaiting (`src/renderer/ChatPanel.tsx:1145-1152`); master prohibits new force unwraps (`00-master.md:48-50`). **Fix:** capture an immutable `{cwd, number, base, headSha}` confirmation target when presenting the dialog, render the dialog from it, and submit that target without rereading live state. Require safe optional handling and a test that changes/clears polled state before confirmation and verifies the original target is sent.

5. **SHOULD — §2.3: Cached ship preview is invalidated only by cwd, not by branch changes.** The spec keeps `.ready` indefinitely for the same directory. Checking out another branch can therefore display and submit the previous branch's title/body, while the server pushes the current branch. Evidence: `05-git-pr-review.md:194-198`; branch refresh explicitly supports terminal-side checkout (`mobile/native/MantaUI/ChatScreen.swift:874-886`); ship input carries cwd/title/body but no preview identity (`src/shared/types.ts:753-763`). **Fix:** invalidate the preview when the observed branch/base changes, discard late preview responses for an obsolete target, and disable Create until a preview for the currently displayed branch exists. Add a same-cwd branch-switch test.

6. **SHOULD — §5.3: LEFT-side threads can attach to the wrong context row.** Matching an old-side note against a `.both` anchor using the same path/line is incorrect after insertions/deletions: context anchors use the NEW line number, whereas LEFT threads use the OLD line number. Evidence: `05-git-pr-review.md:624`; `src/renderer/chatUtils.ts:4474-4490` maintains independent old/new counters and emits the new counter for `both`; `src/server/forge/github.mjs:299-305` preserves GitHub's side and line. **Fix:** match LEFT against `ReviewDiffRow.oldLine` and RIGHT against `newLine` for context rows; use the new coordinate for draft `.both` comments. Add a fixture with unequal old/new offsets and a LEFT context thread, asserting it lands on the correct row rather than a coincidentally equal new-line number.

7. **SHOULD — §2.3: The non-forge chip gating is ambiguous and can violate acceptance.** The mounted view receives the ordinary git `branch`, but `branchState` only checks branch and the global connection boolean. A GitHub-connected box in a git repository with a non-GitHub origin can therefore get an interactive chip unless the implementation happens to pass the forge result's branch instead. Evidence: `src/renderer/chatUtils.ts:4379-4390`; `src/server/forge/index.mjs:735,754-755` returns a null forge branch on context error; `05-git-pr-review.md:206-216,311-312` requires the ordinary label and non-interactive non-forge behavior. **Fix:** explicitly gate interactivity on recognized forge kind plus connection and a valid branch, while preserving the existing ordinary branch label. Test a connected account with a non-forge repository.

8. **SHOULD — §4.2: Device-flow cancellation/lifecycle is incomplete.** Cancel fires an RPC and ignores its outcome, and the spec does not say what cancels the poll task on swipe dismissal or prevents a late start/poll response from reconnecting a dismissed/restarted flow. A retry can race the previous loop. Evidence: `05-git-pr-review.md:450-464`; the existing desktop flow documents/implements one timer and cancellation guards (`src/renderer/ConnectGithub.tsx:146-230`); master requires visible failure handling (`00-master.md:46-50`). **Fix:** define one owner for the loop, cancellation on every dismissal and restart, a generation/identity guard for late responses, and an explicit active-scene wake path that cannot spawn a second loop. Await cancel or explicitly record/report its failure while still allowing local dismissal. Add lifecycle tests for dismissal during start, retry during an outstanding poll, and foreground wake during sleep.

9. **SHOULD — §2.3: The toolbar Done button remains an escape while creation is busy.** `.interactiveDismissDisabled(store.shipBusy)` prevents interactive dismissal, not the explicit Done action introduced immediately above it. The declared cannot-close-while-creating behavior is therefore not implemented by the proposed modifier alone. Evidence: `05-git-pr-review.md:222-225`; desktop blocks the popover's close callback while busy (`src/renderer/SessionHeader.tsx:1235-1238`). **Fix:** disable Done and guard its dismissal action while creating; test both swipe and toolbar dismissal during the operation.

10. **NIT — §8.4: Package ownership is described as unowned.** Master D1 explicitly assigns `mobile/native/Package.swift` and `project.yml` to WS07. Evidence: `00-master.md:183-190`; `05-git-pr-review.md:826-830`. **Fix:** name WS07/the wave-C integration owner as the recipient of this additive mount request rather than calling the package unowned.
