# WS03 review — round1

1. **BLOCKING — F7 / Contracts provided.** F7 explicitly defines a second, incompatible `NewSessionDraft` in `ComposerTextController.swift`: mandatory cwd, UI-chip attachments, and no branch/issue fields. This contradicts the binding shared type and will either redeclare it or break WS04/WS05 integration. **Evidence:** `00-master.md:193-211` defines the sole type in `MantaNavigation.swift`; existing UI chips are `ComposerAttachment` (`mobile/native/MantaUI/ComposerView.swift:26-37`). **Fix:** replace F7 with conversion helpers to/from the master `NewSessionDraftAttachment`; consume the canonical draft, preserve its optional cwd and metadata, and make ready-chip filtering a conversion responsibility. Update signatures, tests, and the provided-contract list accordingly.

2. **BLOCKING — Mount requests / Open questions 3.** The spec defers controller adoption to wave 0 or WS02 in wave B, leaving the C3 provider unreachable during wave A. **Evidence:** binding D3 explicitly assigns this minimal ChatScreen edit to WS03 in wave A (`00-master.md:213-215`); current bindings remain local ChatScreen state (`mobile/native/MantaUI/ChatScreen.swift:264-269,297-309,574-576`). **Fix:** put these exact additive edits in WS03's owned implementation list for wave A and remove the obsolete mount-owner question.

3. **BLOCKING — F2 sendCommand success cleanup.** Testing only draft text equality before clearing *all* chips can delete an attachment added while the command request is in flight. Conversely, if the text changed, already-sent chips remain and can be sent twice. Disabling Send does not freeze attachment controls or C3 insertion. **Evidence:** attachments have stable UUIDs (`mobile/native/MantaUI/ComposerView.swift:26-37`); desktop snapshots submitted attachments and removes only their IDs independently of text cleanup (`src/renderer/ChatPanel.tsx:1580-1588,1605-1613`). **Fix:** snapshot text, agent selections, and ready attachment IDs before awaiting; remove only accepted attachment IDs on success and independently clear text/mentions only if unchanged. Add tests for adding a chip and editing text during the request, plus failure preservation.

4. **BLOCKING — F1 built-in selection / F2 clear confirmation.** F1 preserves immediate built-in selection behavior, including `/clear`, which bypasses confirmation. F2's typed-send path uses a confirmation, so the same destructive operation has inconsistent protection. **Evidence:** `mobile/native/MantaUI/ComposerView.swift:1571-1580` calls `onSlashClear` directly from the palette, whereas `:348-355` provides the actual confirmation dialog. **Fix:** route palette Clear through that dialog too; only perform the reset on confirmation, preserve the draft on Cancel, and test both entry points.

5. **SHOULD — F2 asynchronous dispatch.** The spec sets `commandSending` only inside `sendCommand`, after the possible three-second command lookup, and describes disabling the button rather than guarding the submit entry point. Multiple taps or non-button submits during lookup can dispatch duplicate commands; reading the live draft after the wait can send text different from what was submitted. **Evidence:** current `submit` has no in-flight guard (`mobile/native/MantaUI/ComposerView.swift:1379-1421`), and `canSend` only checks text and uploads (`:1341-1344`). Desktop uses an explicit in-flight guard (`src/renderer/ChatPanel.tsx:1576`). **Fix:** acquire a synchronous MainActor submission guard and capture the draft/chips/delivery before any await, release it on every exit, and route all submit paths through it. Test two submits during lookup and draft editing during lookup.

6. **SHOULD — F5 loading/error states.** Reusing `modelStore.agents` as specified cannot distinguish a failed request from a genuinely empty catalog and cannot retry. A transient connection failure becomes permanent “No matching agents” for the life of this store. **Evidence:** `mobile/native/MantaUI/ChatModelStore.swift:136-143` sets `didLoadAgents` before the request and converts every error to `[]`. **Fix:** request an explicit WS09-owned change exposing agent load failure plus retry, and consume it in the popup with actionable copy. Do not add a second independent fetch. Include failure→retry→loaded acceptance coverage.

7. **SHOULD — Contracts provided / Open questions 2.** Two instructions still oppose binding consolidation decisions: WS05 is told to use `.replace` for failures, and the default proposes changing desktop `useTypeahead.ts` in this PR. **Evidence:** `00-master.md:224` requires `.append`; `:246-250` excludes desktop-renderer-only fixes. The detector is renderer-local (`src/renderer/hooks/useTypeahead.ts:177-194`). **Fix:** change the consumer contract to `.append`, close the desktop question as a reported follow-up, and remove desktop edits/tests from the default scope.

8. **SHOULD — F1 API decoding.** The prescribed `commands` implementation converts a missing/null RPC result into a successfully loaded empty command catalog. That hides a protocol/server failure and can then route a real command as a plain prompt. **Evidence:** `mobile/native/MantaUI/MantaAPIClient.swift:949-959` explicitly provides `callRequired` to prevent this exact empty-success failure; `src/server/opencode.mjs:2856-2873` returns an array for a successful command listing. **Fix:** require an array via `callRequired` for commands and references; test malformed/null results separately from a legitimate empty array.
