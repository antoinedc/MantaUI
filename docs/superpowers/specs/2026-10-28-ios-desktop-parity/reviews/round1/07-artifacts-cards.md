# Round 1 — 07-artifacts-cards

1. **BLOCKING — F4, byte resolution.** The prescribed staging path cannot attach HTTP(S)-backed file/image artifacts. F4 explicitly reuses a helper that sends every non-data URI to `/api/peek`; a remote URL is not a box filesystem path. Evidence: `mobile/native/MantaUI/SessionResourceCards.swift:519-532`; desktop handles remote URLs separately, without the box bearer token, in `src/renderer/ArtifactsPanel.tsx:58-83`. **Spec fix:** define three source branches (data URI, HTTP(S) URL, box path), require successful HTTP status for remote downloads, and explicitly prohibit forwarding the box Authorization header to remote origins. Add source-routing tests and a remote-image attachment acceptance case.

2. **BLOCKING — F6, asynchronous notice lifecycle.** `receive` replaces the current file and resets its phase even while the old file is downloading or its exporter/share sheet is open. The old operation can then mark the new file saved, dismiss it, or present old bytes beneath the new filename; the two-second success timer can likewise dismiss a later notice. Evidence: the specified replacement and unconditional completions in `07-artifacts-cards.md:335-362`; the server can emit several file events in one scanner tick (`src/server/outbox.mjs:298-318`). MainActor isolation does not prevent interleaving across an await. **Spec fix:** capture an immutable event plus generation/operation ID for every download, presentation callback, and delayed dismissal; only mutate the matching notice. Specify button reentrancy, replacement while a picker is open, and dismiss-during-download behavior. Add deterministic injected-download tests for A-starts/B-arrives/A-finishes, old picker completion, and old success timer.

3. **BLOCKING — Pure logic + tests / Package.swift mount.** `WebhookTests.swift` is required to call `MantaAPIClient.makeRequest` and `listOutboxRows`, then is explicitly added to the Linux package. That package does not compile `MantaAPIClient` or its extension. Evidence: `mobile/native/Package.swift:36-60` (explicit production source list); `07-artifacts-cards.md:513-517,615-621`. Simply adding the client is not the stated pure-logic solution: it depends on the Keychain-backed credential store (`mobile/native/MantaUI/MantaAPIClient.swift:8-21`). **Spec fix:** keep wire decoding/formatting tests in the package and place API request tests in a separate Xcode-only test file, or explicitly conditionally compile just the API tests. Clarify the analogous store-test split instead of the ambiguous instruction that store cases must be “#if canImport(UIKit)-free.” Preserve actual MainActor store tests in the app test bundle.

4. **SHOULD — F1, Open plan file failure.** The new plan-file action inherits a silent failure path. The spec only requires the banner for opening the published URL and attaching files; QuickLook staging returns nil and the preview action simply returns. Evidence: `mobile/native/MantaUI/SessionResourceCards.swift:500-506,519-532`. A missing/expired/denied plan file therefore makes the newly shipped control appear dead. **Spec fix:** require the shared inline error banner on every preview/staging failure, including malformed data URIs, with retry possible and the sheet retained. Add an acceptance case for a referenced plan file that no longer exists.

5. **SHOULD — F6/F7, haptics.** The requested direct success generator and webhook-copy haptic bypass the user's haptics setting. Evidence: `07-artifacts-cards.md:366-367` and F7's copy behavior; the existing setting is published by `mobile/native/MantaUI/SessionListStore.swift:71,667-668`, and existing callers gate feedback (`mobile/native/MantaUI/SessionListView.swift:106-108,119-121`). WS10 explicitly exposes that setting as user-disableable (`10-settings-box.md`, Haptics section). **Spec fix:** gate both new haptics on the shared setting (prefer the existing feedback helper), and test/accept that copying a webhook and saving a file remain silent when it is off.

6. **SHOULD — F6 / Mount requests, global visibility.** The acceptance criterion promises a notice on whichever screen is open, but an overlay on `SessionListView` cannot display above its presented Settings full-screen cover or chat resource sheets. Evidence: `mobile/native/MantaUI/SessionListView.swift:151-158`; `mobile/native/MantaUI/MantaAppRoot.swift:97-110`; the proposed mount is `07-artifacts-cards.md:608-613`. **Spec fix:** define modal behavior explicitly: either provide a presentation-layer host that can satisfy the promise, or retain the latest pending notice and show it when the modal closes, narrowing the acceptance text accordingly. Add a Settings-open/resource-sheet-open arrival scenario; do not lose the event merely because its banner is covered.
