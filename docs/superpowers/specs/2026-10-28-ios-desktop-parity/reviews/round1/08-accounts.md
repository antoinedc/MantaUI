# WS08 review — round1

1. **BLOCKING — F3, fresh-seat check before Connect.** Awaiting the existing `accountsStore.refresh()` does not establish that the seat list is fresh or even known. It returns immediately when a fetch is already running, and absorbs fetch errors while retaining old data (initially an empty list). Following the prescribed decision can therefore start a live-login connection despite existing seats, defeating the explicit credential-isolation requirement. **Evidence:** `mobile/native/MantaUI/AccountsStore.swift:163–192`; `src/server/rpc.mjs:269–319` distinguishes isolated seat credentials from the live-login path. **Fix:** specify a freshness-guaranteed, awaitable seat-list operation that joins an in-flight fetch and reports failure. Only choose a flow after successful resolution; on failure leave Connect closed with a retryable error. Test first-load failure, concurrent refresh, stale empty data, and a provider that gains seats during refresh.

2. **BLOCKING — Contracts provided / consumed; F1 and F3 completion.** Model-picker invalidation is not an agreed cross-workstream mount: WS08 says WS09 “should observe” the new notification while declaring no mount requests; WS09 only specifies a reload API and does not subscribe to this notification. Additionally F1 completion never explicitly posts it, although Connect deliberately routes existing-seat providers through F1. Accounts can report a successful connection while the picker retains its process-old models. **Evidence:** `mobile/native/MantaUI/ChatModelCatalog.swift:30–59` loads only once; `docs/superpowers/specs/2026-10-28-ios-desktop-parity/09-models-usage.md:167–173` defines reload but no observer; desktop `src/renderer/AccountsCard.tsx:738–747` refreshes the model catalog after seat addition too. **Fix:** make the observer a mandatory named WS09 mount/contract, mirror it in WS09, and explicitly post after successful seat additions as well as provider/endpoint changes. Add a test that an already-loaded picker changes after F1, F3, toggle and removal, without relaunch.

3. **SHOULD — F4/F5, mutation failure reconciliation.** The unconditional optimistic rollback on any failed upsert assumes the server mutation is atomic. It is not: provider configuration is written before model-selection reconciliation, and a later failure is returned without undoing that write. A transport failure can likewise occur after commit. Snapping back and retaining an unchanged form can misrepresent persisted selection or present an already-created endpoint as unsaved. **Evidence:** `src/server/providers.mjs:528–564` writes configuration, then returns a failing `applyModelSelection` result without rollback. **Fix:** specify a read-back after failed/indeterminate writes, adopt the actual saved state, and distinguish “saved, but could not finish applying” from confirmed rejection. If read-back fails, mark state unconfirmed and offer refresh rather than claiming rollback. Cover partial apply and lost-response cases.

4. **SHOULD — F2 live-seat copy / Open question 3.** The proposed recovery instructions offer switching/removing the live seat even when it is the only seat. That path cannot work: removal rejects `last-seat`, and a managed Claude connection has no Disconnect. The deferral of live re-sign is legitimate, but the replacement copy must not promise an unavailable recovery path. **Evidence:** `src/server/accountsManager.mjs:802–819` requires at least two seats and a usable replacement; `mobile/native/MantaUI/AccountsModels.swift:719` describes the last-seat refusal; `src/renderer/AccountsCard.tsx:120–123` identifies the externally managed login. **Fix:** make copy conditional on an available replacement. For the sole live seat, direct the user to Add account first (when appropriate), or explicitly explain that refreshing the box-owned CLI login is outside this screen. Test sole-seat, no-usable-replacement and usable-replacement variants.

5. **SHOULD — Shared sign-in machinery / F1 retry / F3 installation lifecycle.** Cleanup on failure and retry is underspecified. The 20-second URL timeout and failed PTY exit transition to failure, while Try again starts the whole flow; neither explicitly cancels the prior registered flow before allocating another. Installation also allocates both a login registration and an installer PTY, but the prescribed installing Cancel only kills the latter. These omissions leave pending flows/registrations behind and allow stale asynchronous results to affect a subsequent attempt. **Evidence:** `src/server/rpc.mjs:269–280,313–340` registers login metadata independently of PTY lifetime; `src/server/accountsManager.mjs:845–878` allocates a new pending Claude seat for each add; desktop `src/renderer/AddSeatFlow.tsx:238–248` explicitly cancels the open seat on a failed exit. **Fix:** define one attempt-scoped teardown, tracking every allocated seat/flow/login/installer key, invoked before retry and on failure/cancel/disappearance; ignore results from retired attempt IDs. During installation clear the preserved login registration as well as killing the installer. Add cancellation-during-start, timeout→retry, late-result and installer-cancel tests.

6. **SHOULD — F4 collision guard and F0 independently failing sources.** The collision guard requires a complete endpoint inventory, but the spec allows Add endpoint when that source fails and does not require a fresh successful inventory before Save. An empty/stale `takenIds` then permits an upsert to overwrite an existing endpoint despite the advertised guard. **Evidence:** `src/server/providers.mjs:528–547` replaces the block addressed by the supplied ID; the spec's F0 makes source failures independent and F4 guards only against the available list. **Fix:** disable creation with an actionable retry while the inventory is unknown, and recheck collision against a successful fresh list before saving. Document that this is a client-side check, not cross-device atomic uniqueness. Test failed initial inventory and a collision introduced after testing.
