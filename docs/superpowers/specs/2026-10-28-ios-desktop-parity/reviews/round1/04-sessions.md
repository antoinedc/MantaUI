1. **BLOCKING — §2, §13: the launcher plumbing omits the actual WebSocket owner.** Adding a launcher to `TerminalWebView` and `TerminalURLBuilder` does not transmit it: `TerminalSocket` owns URL construction and has neither a launcher initializer parameter nor stored launcher state. It is also absent from the owned-files/mount list. Evidence: `mobile/native/MantaUI/TerminalWebView.swift:432-438` constructs the socket; `mobile/native/MantaUI/TerminalSocket.swift:31-69` defines its inputs and `:122-123` calls the URL builder without a launcher. **Fix:** obtain an explicit additive ownership amendment for `TerminalSocket.swift`, require launcher propagation through its initializer and every reconnect, and test the socket's actual request URL (not only the standalone URL builder). Preserve the bearer header.

2. **BLOCKING — §12, §15, §17.2: the pinned draft contract contradicts master D2.** The spec declares only cwd/text/attachments and explicitly tells the scaffold to use that exact shape. It omits `worktreeBranch` and `linkedIssueURL`, and the consumer has no behavior for either. Inbox-originated drafts therefore cannot preselect their requested branch or show the originating issue. Evidence: `docs/superpowers/specs/2026-10-28-ios-desktop-parity/00-master.md:193-210` declares the sole five-field type and required behavior; `04-sessions.md:929-965` specifies the incompatible type and prefill. **Fix:** reference D2's existing declaration instead of defining a competing contract; add branch-prefill precedence over the box default, the issue-link header, and tests for both, including preservation through the create flow. Remove the superseded open question.

3. **SHOULD — §7: destructive confirmation counts exclude windows that will actually be closed.** The spec explicitly counts only visible windows, but close-project operates on the whole tmux project and removes worktrees belonging to all its windows. Hidden background-job windows can therefore be stopped or have worktrees removed without being included in the confirmation. This is not desktop parity. Evidence: `mobile/native/MantaUI/SessionListStore.swift:264-275` filters job windows out of visible projects; `src/renderer/Sidebar.tsx:1050-1061` counts all project windows, and `:305-325` processes all their worktree paths. **Fix:** compute destructive-action counts from the complete project, including hidden jobs, while retaining visible counts for ordinary header chips. Add a test with one visible parent and a hidden running job/worktree.

4. **SHOULD — §8: a single dirty-worktree prompt can overwrite another pending deletion's decision.** The preserved undo mechanism commits every expired deletion in a loop and starts independent asynchronous operations. If two worktrees are dirty, both can assign the one `worktreePrompt`, leaving one request without a presented decision. The existing undo haptic also fires before any deletion succeeds, even when the new outcome is 'needs decision' or failure. Evidence: `mobile/native/MantaUI/SessionListStore.swift:584-617`; `mobile/native/MantaUI/SessionListView.swift:612-620`; proposed singleton prompt in `04-sessions.md:715-722`. **Fix:** specify serialized close processing or a queued prompt model keyed by project/window, preserving all unresolved requests. Move success feedback to actual `.closed` completion. Test two expired dirty deletes and mixed dirty/failed/successful outcomes.

5. **SHOULD — §2: launcher discovery conflates unavailable data with an uninstalled CLI.** The spec resets launchers to `[]` on fetch failure, then resolves any saved CLI absent from that array to Chat. A transient network failure (or opening a destination before discovery finishes) silently changes the selected behavior and can make the mode menu disappear. Evidence: `04-sessions.md:159-190`; `mobile/native/MantaUI/SessionListStore.swift:209-235` publishes projects before awaiting its decoration fetches; `src/server/launchers.mjs:37-60` returns an authoritative installed list only on successful discovery. **Fix:** distinguish loading/error/loaded, retain the last successful list, and downgrade a persisted CLI only after a successful authoritative response. Specify a visible loading/retry state when there is no usable snapshot. Test initial loading and transient failure with a saved CLI mode.

6. **SHOULD — §6, §15: the shared device-flow contract is not fully incorporated.** Master D5 requires this implementation to satisfy WS05 §4, but this spec only pins sleep-first polling and a formatted countdown. It does not require deadline-based local expiry, guarded foreground resumption, or the Copy link action that WS05 expects. Evidence: `docs/superpowers/specs/2026-10-28-ios-desktop-parity/00-master.md:217-219`; `05-git-pr-review.md:443-465` and `:471-483`; `04-sessions.md:560-568`. This matters when Safari backgrounds the app during sign-in. **Fix:** explicitly adopt the complete shared behavior from WS05 under the WS04-owned types: absolute deadline, expiry transition, one polling owner, foreground polling only when the interval has elapsed, Copy link with feedback, and cancellation checks after awaits. Add clock-injected expiry/resume tests and publish one agreed view/store API for WS05 to consume rather than leaving the names and ownership unresolved across the two specs.
