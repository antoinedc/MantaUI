# WS02 review — round1

1. **BLOCKING — F5, editing access to zero rules.** The card permits deleting every rule and `canStart` only rejects empty fields in remaining rows. Sending `tools: []` does not remove access: the server restores the originally requested tools. Thus the UI can say “No tools declared” while approving all original access. Evidence: `src/server/delegate.mjs:4783–4787` selects edited tools only when their length is positive. **Spec fix:** under D7's no-server-change constraint, disable Start when the edited list is empty and explain that this request must be declined instead. Test removing the final rule and ensure no approve RPC is issued. Do not claim an empty edited list means deny-all.

2. **BLOCKING — F5, silent auto-approval from pending permissions.** `store.permissions` is a list of unanswered requests, not previously granted permissions. Its `always` patterns describe what could be saved if approved. Copying the desktop helper would silently authorize a background job using access the user has not granted. Evidence: `src/shared/opencodeV2.mjs:470–490` maps the request's `save` into `always`; `src/server/streamInterp.mjs:957–971` adds requests on `permission.asked` and removes them on reply; `mobile/native/MantaUI/ChatSessionStore.swift:615–628` copies that pending list. **Spec fix:** remove this auto-approve path and require explicit approval when trust is off. Record the desktop behavior as a separate bug under D10. Add a test that a matching unanswered parent permission never approves a job.

3. **BLOCKING — F2, compaction state lifetime.** The proposed timer clears only `ChatSessionStore.compaction`, while the event-store snapshot retains `.done`; `transcriptStale` similarly clears only the store property. Every subsequent snapshot can restore the old card and restart its timer, or an unrelated frame can cancel the visible effect of clearing it. Evidence: `mobile/native/MantaUI/ChatSessionStore.swift:556–580` copies accumulated snapshot fields on each application; `mobile/native/MantaUI/MantaEventStore.swift:64–107` is persistent per-session state. F2 explicitly instructs restarting the timer whenever the snapshot phase is done. **Spec fix:** define a compaction generation/sequence and consume each phase transition once; clear the reducer's compaction on `transcriptStale`, and tombstone expired generations in the store. Schedule expiry only on a new ended transition. Test unrelated frames during/after the three-second window, stale followed by an unrelated frame, and a new compaction while an old timer is pending.

4. **BLOCKING — F10, tail-count windowing cannot keep a message anchored.** Setting `messageLimit = n - i` then fetching the latest N messages assumes no messages arrived between the two fetches. A new message shifts the window past the target, and subsequent turn-boundary refetches keep dropping older messages while focus is active. Turning auto-scroll off after `focusSeq` also happens after the replacement rows have been published. Evidence: `mobile/native/MantaUI/ChatSessionStore.swift:996–1026` fetches a tail window by count, `:1056–1065` replaces the messages/blocks, and `:689–692` schedules refetches at turn boundaries; `mobile/native/MantaUI/ChatScreen.swift:424–429` independently scrolls to bottom when a blocking card arrives. **Spec fix:** retain a target-ID anchor and derive a focused presentation slice locally from the fetched history; widen/revalidate on subsequent fetches so the target remains loaded. Disable following before changing rows and suppress the blocking-card bottom jump while focused. Specify failure/cancellation and concurrent-focus handling, including that an already-in-flight fetch currently returns immediately (`ChatSessionStore.swift:998–1001`). Test a message appended between lookup and focus, completion refetch while focused, and a new permission card.

5. **BLOCKING — F11 / mount requests, incompatible WS01 contract.** WS02 publishes `commandByMessageID: [String: StreamCommandExecutedPayload]`, whereas WS01 expects `liveCommandsByMessageID: [String: OpencodeCommandOrigin]` and a different optionality for `arguments`. WS02 also fails to explicitly accept WS01's mapping/media subscriptions and truncation-notice suppression mounts. Both specs can be implemented literally without the transcript consuming these features. Evidence: WS01 `01-transcript.md:818–819` defines the mapper's inputs and `:897–901` specifies M3a–M3e; current mapper calls are in `mobile/native/MantaUI/ChatSessionStore.swift:1065` and its refresh helpers. **Spec fix:** reconcile one command payload/property contract in both specs, list the conversion into `TranscriptMapOptions`, and explicitly include WS01 M3a–M3e in WS02's wave-B deliverables and integration tests. Include focus mapping with those same options rather than mapping the message with default options.

6. **SHOULD — F5, approval result copy and refresh races.** `ok:false` proves only that the request is no longer pending; it does not prove expiry or that the agent was told no. Another device may already have approved it. Also an in-flight poll can restore the card after a successful local decision unless results are versioned/tombstoned. Evidence: `src/server/delegate.mjs:2501–2505` returns false whenever the pending entry/resolver is absent; `src/server/rpc.mjs:2475–2480` returns that boolean without a reason. **Spec fix:** use “That request is no longer pending” for false, refresh authoritative state, and discard stale fetch responses for resolved approval IDs. Add approve-on-another-device and poll-finishes-after-local-approve cases.

7. **SHOULD — F4, identical errors are not distinct occurrences.** Dismissing by payload equality can suppress a later identical authentication failure indefinitely within a turn. The prose says a new error shows again, but the implementation contract has no occurrence identity. Evidence: `mobile/native/MantaUI/ChatSessionStore.swift:580` copies `s.sessionError`; `src/server/streamInterp.mjs:751–757` emits a payload without an error ID. **Spec fix:** add a session-error sequence in the router, dismiss a sequence rather than a value, and clear dismissal on a new turn. Test two identical payloads separated by a dismissal.

8. **SHOULD — F6, read-only ownership must survive connection gaps.** The ownership store only refreshes on appear and `delegate.updated`, and a failed initial read explicitly enables the composer. A missed update or failed classification therefore leaves a background job writable with no recovery until a later job event. Evidence: `mobile/native/MantaUI/ChatSessionStore.swift:261` makes `isReadOnly` immutable at construction, and `:383–389` initializes it before asynchronous ownership resolution; `:1430` and `:1447` use that flag for mutation guards. **Spec fix:** define resolving/known-job/ordinary-session states, disable mutations during initial resolution, retain known ownership on failures, and retry on reconnect/foreground. State how the resolved policy reaches store mutation guards, not merely composer visibility. Test initial failure then reconnect and missed job updates.

9. **NIT — ownership / mount requests / open questions.** Several questions were already settled by the binding master: Q1 ownership is granted by D1, Q2 must use the navigator under D9, and the real navigation mount is `MantaAppRoot.swift`, not capture-fixture `RootView.swift`. WS06 is in the same wave as WS02, so it cannot apply its own ChatScreen mount as a “later-wave owner.” Evidence: `00-master.md` C4, Waves, D1 and D9; WS02 M2 and the final mount paragraph disagree. **Spec fix:** remove settled questions/fallbacks, name `MantaAppRoot.swift`, and explicitly assign the same-wave WS06 chat-search mount to WS02 (or serialize it after WS02).
