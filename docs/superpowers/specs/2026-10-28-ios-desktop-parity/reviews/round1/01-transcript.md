# WS01 review — round1

1. **BLOCKING — F6, read-only reply actions.** `cards != nil` does not mean a writable chat. The subagent screen explicitly injects a non-nil `TranscriptCardActions.readOnly`, whose quote callback does nothing. Following this spec exposes two dead Quote controls in the subagent drill-in and its selection sheet. **Evidence:** `mobile/native/MantaUI/ChatScreen.swift:1616-1619`; `mobile/native/MantaUI/TranscriptRow.swift:207-226`. **Fix:** define an explicit quote capability (optional callback or capability flag) in the WS01-owned action type, absent for read-only actions; gate both menu surfaces on it. Add a read-only action-availability test.

2. **BLOCKING — F1, media ownership and reconciliation.** The store is nested by message, but begin and show can belong to different assistant messages. Matching/deduplicating only within the incoming message leaves the original placeholder pending and emits another row with the same handle ID; the server deletes the pending handle on show, so no later fail will repair it. Canonical reconciliation must also find a handle across messages, not just within one message's media. **Evidence:** `docs/opencode-plugins-v2/manta/tools/media.ts:17-21` forwards the calling message on every call; `src/server/media.mjs:308-316,348-360` emits the current show's message and deletes the pending handle; `mobile/native/MantaUI/ToolActivity.swift:655-656` documents one assistant message per model step. **Fix:** pin session-wide handle lookup and one authoritative owning-message policy for live and canonical data. Test begin in A, show in B, canonical refetch, and app reload: exactly one ready row, no pending row and no duplicate stable ID. Define deterministic ordering for equal/nil `beganAt` as well.

3. **BLOCKING — F6 / Contracts consumed, new-session semantics conflict with master.** WS01 explicitly retains immediate `forkSession(seed:)`, whereas binding D2 requires Quote in new session to use `NewSessionDraft` and the create sheet with a user confirmation. **Evidence:** master `00-master.md`, D2 and C3; existing `mobile/native/MantaUI/ChatScreen.swift:968-1009` immediately calls the fork RPC and navigates. **Fix:** replace the retained-fork instruction/acceptance with the D2 flow and name the cross-owner callback mount (WS03/WS04). Specify that the quote seeds the composer and is never auto-sent.

4. **BLOCKING — M3a/M3e, cross-workstream command contract.** WS01 consumes `liveCommandsByMessageID: [String: OpencodeCommandOrigin]` with optional arguments. WS02 instead promises `commandByMessageID: [String: StreamCommandExecutedPayload]`, whose arguments are required. These are not the same property or value type; the prescribed mount cannot compile against the other spec. **Evidence:** `02-chat-cards-queue.md:661,666` versus WS01 M3a/M3e; actual server frame is `src/server/streamInterp.mjs:1037-1040`. **Fix:** agree one published property and explicitly define the conversion to `TranscriptMapOptions.liveCommands`, including absent/null arguments. Put the same contract in both specs and test durable-origin precedence over the live value.

5. **SHOULD — F1, reserved geometry guarantee.** Porting `applyMediaEvent` does not preserve the pending box dimensions: show overwrites width/height with measured dimensions (or null). Canonical reconstruction then uses only the show's output. A declared 16:9 placeholder followed by a square image changes height, contrary to the stated no-jump acceptance. **Evidence:** `src/renderer/chatUtils.ts:4759-4779`; `src/server/media.mjs:359-360`; `docs/opencode-plugins-v2/manta/tools/media.ts:110-113`. **Fix:** explicitly choose immutable begin geometry while a handle is live, and define canonical reconstruction from the matching begin if continuity across refetch is required. Add mismatched-dimension and video-with-no-measured-dimensions tests; do not claim the desktop reducer already guarantees this.

6. **SHOULD — F1, staging cache scope and lifecycle.** A process-wide cache keyed only by box path can show a previous box's file after removing/re-pairing the server: common absolute paths need not identify the same content across boxes. No invalidation, cleanup, or stale-file policy is specified. **Evidence:** `mobile/native/MantaUI/MantaAPIClient.swift:4-12,20-21` binds requests to the currently paired server, while WS01 F1 specifies a static stager keyed by path alone; master WS10 includes removing the server. **Fix:** scope cache and in-flight work to server/pairing identity plus source, cancel/clear on pairing changes, and define temporary-file cleanup. Test two boxes with the same remote path and ensure the second cannot receive the first's cached bytes.

7. **SHOULD — F4 / M3d, dropping truncation warnings prematurely.** Presence of a message in `messages` is not proof that a footer displays its truncation. The mapper skips incomplete assistant messages; additionally, the transcript includes raw finish only inside a `step-finish` part when tokens exist. A live warning can therefore be lost by the prescribed suppression rule. **Evidence:** `mobile/native/MantaUI/ChatModels.swift:189-191`; `src/shared/opencodeV2.mjs:251,276-289`; `src/server/streamInterp.mjs:885-893` classifies live raw finish independently of transcript availability. **Fix:** suppress the tail notice only when an emitted footer actually carries that message's warning; retain the live per-message kind as a fallback until canonical classification succeeds. Test a live truncation followed by incomplete and missing-usage transcript snapshots.

8. **SHOULD — F1/F2, unbounded payload assumptions.** The media path checks unknown sizes only after downloading the entire file into memory; the tool-output section also incorrectly assumes full canonical output is bounded by the 20,000-character streaming cap. These are significant phone-memory risks, especially for inline data URLs and large videos/tool outputs. **Evidence:** `mobile/native/MantaUI/MantaAPIClient.swift:559-570` uses `session.data(for:)`; `src/server/streamInterp.mjs:81,410` caps streamed chunks, not canonical transcript output. **Fix:** distinguish live-output limits from canonical output and prescribe bounded presentation for full output. For media, define a bounded fetch/staging method through C1 (or explicitly accept the full-download limitation and narrow the acceptance claim); include unknown-size oversized media/data-URL tests. A syntax/private-access constraint should not be treated as a memory bound.
