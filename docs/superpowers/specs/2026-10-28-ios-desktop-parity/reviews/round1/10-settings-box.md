# WS10 review — round1

1. **BLOCKING — API layer / F9 / cross-workstream contract.** WS10 declares `MantaAPIClient.forgeStatus()` returning `ForgeStatus`, while WS05 declares the same zero-argument method returning `GitForgeStatus` and explicitly says WS10 must not add another. The contracts also disagree about validation (`validate:true` versus no input). Wave A cannot depend on an implementation supplied only in wave C. **Evidence:** `05-git-pr-review.md:48-50,861-862`; `src/server/rpc.mjs:952` uses the input flag to decide validation. **Fix:** assign this method and its wire type to one wave-A owner, pin a validation parameter/default, and have WS05 consume it. Update both specs' provided/consumed contracts; do not rely on return-type overloads in extensions to resolve ownership.

2. **BLOCKING — F1 acceptance / F5 persistence note.** F1 promises that a rejected worktree toggle reverts, but explicitly uses the existing generic toggle and `commit`. F5 changes only the haptics toggle, not `commit`, so its referenced note does not implement F1's promise. **Evidence:** `mobile/native/MantaUI/SettingsScreen.swift:284-297` calls `commit`; `MantaSettingsStore.swift:113-127` changes the published value before the request and only sets an error on failure. The awaited alternative is at `MantaSettingsStore.swift:130-150`. **Fix:** specify an awaited, failure-safe path for both worktree toggles (or explicitly fix commit with ordering protection), disable/serialize writes while saving, and add injected-store tests proving failure preserves the confirmed value and surfaces feedback.

3. **BLOCKING — F18 transient update failures / C1 API implementation.** The proposed transient classifier is not desktop parity: it omits proxy-origin failures and treats every `MantaError.transport` as a restart, including malformed/missing RPC responses. More importantly, the existing Swift RPC transport discards HTTP status except for 401/upgrade detection; an HTML 502 becomes a JSON parsing error, not either proposed transient type. A successful proxied restart can therefore be reported as a failed update. **Evidence:** `src/renderer/chatUtils.ts:1384-1410` explicitly handles 502/503/504/521/522/524 and excludes structured self-update failures; `mobile/native/MantaUI/MantaAPIClient.swift:923-937,984-1000` parses JSON after losing status. **Fix:** pin a status-preserving update transport/error contract, with the required C1 foundation-owner mount request rather than an unauthorized client edit. Test HTML/text proxy 5xx, network loss, ordinary 500, malformed 200, 401, and structured `{ok:false}` separately; only genuine restart-compatible failures should keep waiting.

4. **BLOCKING — F15/F17 sign-out and APNs cleanup claim.** The statement that unregistering locally makes the box prune a dead APNs token on its next send is not established by this implementation. Device revocation only revokes the bearer; APNs registrations are a separate store without a device association, and fanout sends all stored tokens. F17 does not even invoke local unregister on the revoked phone. Local unregister also cannot guarantee that the old box stops sending after this app registers again for a different box. **Evidence:** `src/server/auth.mjs:592-599`; `src/server/push.mjs:96-130,769-798`; `mobile/native/MantaUI/MantaAppDelegate.swift:155-175` registers again on launch/after pairing. **Fix:** remove the unsupported pruning guarantee and resolve the privacy contract explicitly with the master owner. Reliable remote sign-out needs device-associated push revocation/filtering and tests (including remove A → pair B and remotely revoke another phone); that requires a D7 amendment before implementation. If deliberately deferred, explicitly document the continuing-notification limitation rather than promising complete sign-out.

5. **SHOULD — F15 removal ordering and failure states.** “Always” delete credentials and post the removal notification has no defined outcome if Keychain deletion fails. The spec also orders the root transition before a warning alert that it says must be acknowledged before leaving. A literal implementation either loses the warning or reports a removal that is undone on relaunch. **Evidence:** `mobile/native/MantaUI/KeychainCredentialStore.swift:66-70` throws on deletion failure; `MantaAppRoot.swift:38` derives paired state from those credentials on launch. **Fix:** define a removal state machine: remote result → successful local deletion → optional warning acknowledgment → root notification. On local deletion failure show an actionable error and retry local deletion without repeating a successful remote revoke. Add tests for deletion failure, remote 401, offline/shared pairing, and warning acknowledgment ordering.

6. **SHOULD — F7 preview failure state.** “Render no status line” avoids falsely claiming no backup, but leaves an initially failed preview without an actionable error or retry behavior. The spec does not define whether Restore is visible/enabled with no valid preview. **Evidence:** `src/renderer/Settings.tsx:632-640` does swallow preview failures into null; this is an existing desktop limitation, not a sufficient implementation contract under master ground rule 2. `src/server/rpc.mjs:1177-1197` distinguishes a successful no-backup response from a failed request. **Fix:** retain the rule against fabricated backup status, but add a separate “Couldn't load the saved window layout” error + Retry, and disable/hide Restore until a successful preview. Test initial failure and refresh failure after a previous successful preview.

7. **SHOULD — F14 manual fallback on private/tailnet boxes.** The footer tells the user to type “this server's address,” but the defined screen only displays the six digits and Server ID. On a private box that ID derives a public hostname which is not the reachable address; the QR correctly carries a private override, but the manual fallback does not display it. **Evidence:** `src/renderer/pairPanel.ts:46-74` documents why the private override is necessary; `mobile/native/MantaUI/MantaPairingModels.swift:41-44` derives the public hostname from an ID. **Fix:** display/copy the actual normalized connected server URL beside the manual code, especially when a private override is present. Add an acceptance case pairing manually from a Tailscale box using only information visible on Add a device.

8. **SHOULD — F21 manual-address validation / T10.** The claimed “blank/garbage → nil” behavior cannot follow merely from prefixing `https://` and calling the existing normalizer. That helper checks only the prefix and trims slashes; it does not validate a host, credentials, query, or fragment. T10's “garbage” case is unspecified and could be implemented inconsistently. **Evidence:** `mobile/native/MantaUI/MantaPairingModels.swift:46-53`. **Fix:** define accepted URLComponents/host/port rules and concrete rejected inputs (empty host, whitespace, userinfo, unsupported scheme, query/fragment, invalid port), preserve explicit HTTP for private listeners, and list exact test inputs and normalized outputs. Keep these checks in the owned pairing helper.
