# Round 1 — 06-search

1. **BLOCKING — Mount requests §1 / F3: chat-search mount has conflicting owners and timing.** WS06 explicitly delegates the ChatScreen edit to WS02 and forbids its own edits outside the listed files, but WS02 explicitly leaves the WS06 search button for its owner in a later wave. Both run in wave B, so following both briefs leaves the entry point unimplemented (or causes concurrent ChatScreen edits). **Evidence:** `02-chat-cards-queue.md:773–776`; master C4 assigns ChatScreen to WS02 and master Waves places WS02/WS06 together in B. **Fix:** pin WS02 as the chat mount implementer, amend the contradictory WS02 instruction, and specify the integration order: WS06 delivers SearchScreen first, WS02 adds the mount after its message handler works. Alternatively explicitly serialize a WS06 mount after WS02 finishes, with an ownership exception in the master and both specs.

2. **SHOULD — F1 request semantics / XCTest item 5: raw-query requirement diverges from desktop.** The spec intentionally tests sending untrimmed text, but desktop trims before sending. The server preserves leading/trailing whitespace in the actual LIKE pattern and substring match; it only trims to detect an empty query. A pasted ` foo ` therefore misses messages that desktop finds for the same input. **Evidence:** `src/renderer/SearchPalette.tsx:70,113`; `src/server/messageSearch.mjs:60–69,101–104,143–144`. **Fix:** retain raw text in the field but send the whitespace/newline-trimmed query, and replace the untrimmed encoding test with a request-normalization test.

3. **SHOULD — F1 SearchStore cancellation and stale-result rules: cancellation must not become a visible failure.** The recipe cancels a task on every query change and unconditionally maps caught errors to `.failed`. A cancelled sleep/request can therefore overwrite a newer loading/results state or show an error during ordinary typing. The existing stale-success test does not cover this. **Evidence:** spec F1 Store bullets (`06-search.md:205–210`); desktop guards catch and finally as well as success with the sequence check (`src/renderer/SearchPalette.tsx:114–123`). **Fix:** require every state mutation after suspension, including catch/cleanup, to check the current sequence; treat cancellation as an expected exit rather than failure. Invalidate outstanding sequences even when the new query is below minimum and cancel on dismissal. Add tests for cancelled debounce, stale request failure, and clearing while a request is in flight.

4. **SHOULD — F1 acceptance criteria: “network/server failure … never no results” exceeds the existing wire contract.** RPC transport/envelope failures can be displayed, but DB and worker failures deliberately return a successful empty response. The client cannot distinguish those from a genuine empty search. **Evidence:** `src/server/messageSearch.mjs:92–97`; `src/server/rpc.mjs:2017`; the spec's own Wire semantics documents this degradation. **Fix:** limit the acceptance criterion to transport/RPC-envelope failures and explicitly record DB/worker failures as an inherited server limitation. Keep the no-server-change scope required by master D7; do not promise detection the response cannot support.
