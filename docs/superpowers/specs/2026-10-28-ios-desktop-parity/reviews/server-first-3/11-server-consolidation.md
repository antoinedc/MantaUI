## Findings

1. **BLOCKING — D11 enqueue classification makes every non-user item transparent, including visible background results.**
   - **Problem:** “Boundaries — classification data” unconditionally assigns `raw.type !== "user"` to `transparent`. Rule 3 in the same spec correctly says an assistant `background-result` draws and ends a run. V2 delivers background-child results as synthetic records, so these rules disagree on a normal result-delivery path: A → visible background result → B can stay one run live but become two runs canonically. The new test that all non-user items are transparent would cement that drift.
   - **Evidence:** `11-server-consolidation.md` D11 rule 3, “Boundaries — classification data,” and event-parity test (6). `src/shared/opencodeV2.mjs:322–327` documents synthetic subagent results; `mapBackgroundResult` at `:371` constructs the assistant result. `src/shared/opencodeV2.test.mjs:349–368` verifies that subagent synthetics produce visible `background-result` parts while other synthetics are dropped. `src/server/streamInterp.mjs:95–119` filters non-user items for the *pending-user inbox*; that filtering is not a transcript-visibility rule.
   - **Spec fix:** classify raw delivered items according to their mapped transcript outcome. A synthetic subagent result that maps to a visible background-result is a boundary; genuinely hidden synthetics are transparent. If the enqueue payload lacks the metadata needed to distinguish them, leave its class unknown and use the buffered delivered-message lookup. Pin the live placement/handover of that visible boundary as well. Add A → native synthetic background result → B parity coverage separately from the existing hidden-synthetic and legacy completion-user-message cases.

2. **BLOCKING — D11's degraded boundary fallback has no mechanism to make the promised canonical repair authoritative.**
   - **Problem:** on timeout/error/reconnect/buffer overflow, the spec chooses `draws` and promises the turn-end canonical fetch repairs any membership difference. Elsewhere, canonical annotation substitutes the ledger's view for known run ids; single-message fetches explicitly stamp membership from the ledger; client views merge monotonically and retain ledger state. No rule invalidates or rebuilds the guessed ledger membership. If the actual boundary was transparent, A and B should share id A, but the fallback ledger records B under id B. Even if a full fetch renders canonical A+B once, a later splice or continued tool event can stamp B again and restore the split. This is persistent drift, not merely the acknowledged one-time row replacement.
   - **Evidence:** D11 “Failure / reconnect” versus “Run revisions” (canonical uses known ledger view), the paragraph after the `toolRuns` schema (`getMessage` stamps ledger membership), and “Lifetime” (execution end does not reset the ledger). The existing desktop splice replaces a message with its returned annotated parts (`src/renderer/hooks/useTranscriptState.ts:219–240`), so stale ledger membership is observable after the supposed repair.
   - **Spec fix:** mark guessed boundaries/affected ledger ranges as provisional, then define a server-side canonical rebuild and invalidation when authoritative history is available. Reconcile both membership and summaries, retire superseded run ids, and publish an explicit replacement that both client reducers accept without being defeated by old revisions. Guard late lookup results and events during the rebuild. Test lookup timeout on a truly transparent boundary → canonical repair → later `getMessage` and tool update: all paths must keep the repaired id A, with no resurrection of B or lost parts.

3. **SHOULD — make WS11's connection-epoch plumbing an explicit integration deliverable, not only a reducer contract.**
   - **Problem:** D11 correctly assigns epoch behavior to both clients and mentions iOS `applyRunningSet`, so this is not an unowned blocker. However, M-11-4 names only the new stream cases, M-11-11 lists desktop methods, and the tests predominantly feed epoch/context values directly into pure reducers. They do not prove the global snapshot reaches the epoch owner or that real transcript/splice requests capture the connection generation. No WS02 implementation currently in progress should be assumed to provide that future contract.
   - **Evidence:** `src/server/streamInterp.mjs:1062–1069` emits `runningSet` as a top-level bus kind, not a `stream` sub. Desktop has a separate `onRunningSet` subscription (`src/renderer/api/httpApi.ts:1159`) and connection transition handling (`:630–646`); `useSseBus.ts` principally consumes `onStreamEvent`. iOS handles the snapshot separately in `MantaEventStore.swift:568–587`. WS11 D11 and M-11-4/11 contain the wave-D ownership but not the complete receiving path in the traceability rows.
   - **Spec fix:** explicitly list WS11-owned changes to `RunningSetPayload` / `StreamRunningSetPayload`, the persistent epoch/generation owner, desktop `onRunningSet` routing, iOS connection transitions and `applyRunningSet`, and request-generation capture in canonical/splice fetches. Add receiver-level tests through actual bus routing and mocked RPC completion, including opening a chat after the initial snapshot has already arrived. Keep these changes in wave D; do not send them back to the active WS02 worker.

4. **SHOULD — cross-cutting S1 remains open; the response table incorrectly says there was no cross-cutting file.**

The master inventory nevertheless omits both `apiVersion()` members, uses shorthand close-method signatures, and records only the B-era truncation factory. M-09-4 still omits the media reset already assigned to IB by D22. WS11 D6 also retains the shorthand signatures despite its explicit member table having labeled ones. The new response heading says “no cross-cutting file this round,” overlooking the requested report.
   - **Evidence:** `00-master.md:374–375,499,546,692,698,720`; WS11 D6 iOS switch (`:793`), client-member table (`:1972–1979`), and “Review responses (server-first-2).” These are the exact four gaps listed in `reviews/server-first-2/00-cross-cutting.md` S1.
   - **Spec fix:** reconcile the master and WS11 inventories: add both `apiVersion` methods; use `sessionsClosePreview(project:windowIndex:)` and `sessionsClose(project:windowIndex:dirtyWorktree:)` consistently; append a D8-qualified `from(payload:)` note without changing the B contract; record D22's already-owned media reset in M-09-4. Acknowledge cross-cutting S1/S2 in the response table. Preserve existing wave ownership; these edits do not create a new B implementation assignment.
