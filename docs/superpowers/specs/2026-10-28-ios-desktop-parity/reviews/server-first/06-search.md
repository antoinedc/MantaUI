# Server-first review — 06-search

1. **BLOCKING — Q1 RPC wiring / M-06-srv-1: a failed initial topology read becomes a successful empty search.** The specified adapter assumes `refreshNow()` rejects when discovery fails. It does not: it catches the failure, sets `stale`, and retains the initial empty projects array. Consequently, list-entry search returns empty groups without `degraded`, and chat-entry search searches only the supplied primary while claiming the full box scope. This defeats Q3's failure/no-matches distinction. **Evidence:** `06-search.md:179–195`; `src/server/syncState.mjs:42–45,58–95,105–106`; `src/server/messageSearch.mjs:61–64` returns success for empty scope. **Fix:** after the initial refresh, check `everSucceeded()` again and throw a scope-unavailable error if still false, letting Q1 produce `degraded:true`. Define whether a previously successful but now stale snapshot is acceptable (last-known-good is reasonable). Add an RPC integration test using a real sync-state instance with a failing injected `listProjects`, rather than testing only a directly throwing search dependency; also test a successful genuinely empty snapshot.

2. **BLOCKING — Desktop migration, closed-session jump: the palette still closes before its new feedback can be read.** The spec changes `jump` to set an inline message when the owner is gone, but leaves the shared activation/close mechanics unchanged and does not authorize a `PaletteShell` edit. `PaletteShell` unconditionally starts closing after every `onPick`, for both mouse and Enter; the message disappears when the palette unmounts 100 ms later. Thus the promised actionable result remains effectively a dead click. **Evidence:** `06-search.md:357–360,378–379`; `src/renderer/PaletteShell.tsx:13–15,41,47,53–55`; `src/renderer/SearchPalette.tsx:176–180` supplies the callback without any success result. **Fix:** pin a backward-compatible way for selection to veto dismissal (for example `onPick: (...) => void | false`, closing unless the result is `false`), return that result through SearchPalette, and authorize/ledger the shared-shell change after checking other wave-B consumers. Test both mouse and Enter with a missing owner, advance past the close timer, and assert the palette and feedback remain visible and `onClose` was not called. Successful picks must still close.

3. **SHOULD — Q2 / Desktop rendering: use the server's label rather than reconstructing it.** iOS renders `group.label`, but the desktop instructions still pass workspace/name separately to `SectionHeader`, which constructs its own breadcrumb. This retains a second label/fallback policy and can disagree with the required raw-session-id fallback when only one label component is known. **Evidence:** `06-search.md:199–205,347–350`; `src/renderer/SearchPalette.tsx:282–305` composes the workspace/session header locally. **Fix:** pass the server's `label` as the complete non-current section title and remove the local workspace-prefix construction from this consumer. Add a response fixture whose supplied label differs from the components, plus a missing-component fixture, asserting both clients display the supplied label verbatim.

4. **SHOULD — Legacy compatibility: pin label-enrichment failure behavior and primary inference in tests.** The direct CTO caller remains compatible because it calls `searchMessages({query, sessionIds})` without dependencies and reads only `supported`/`hits`. Old desktop requests, however, now receive the RPC adapter's `listProjects` dependency even though their search scope is already supplied. The spec says legacy behavior is unchanged but does not define what happens when this optional label lookup fails, nor explicitly test preservation of the first-session primary/cap behavior. **Evidence:** `06-search.md:174–182` and node test 9; `src/server/cto.mjs:398–412`; `src/server/messageSearch.mjs:55–57,84–89`. **Fix:** state that legacy search scope/caps come exclusively from the legacy arguments, with `sessionIds[0]` retaining the default primary cap of 50; optional label lookup failure must fall back to unknown labels without discarding hits. Add legacy tests with no dependency and a failing label dependency, multiple sessions, and explicit cap overrides. The new `scope:"all"` path must continue to fail as degraded when discovery is unavailable.
