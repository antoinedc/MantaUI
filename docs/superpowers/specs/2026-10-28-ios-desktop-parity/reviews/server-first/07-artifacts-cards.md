# Server-first review — 07-artifacts-cards

1. **BLOCKING — Server-first: published-page resolution.** The proposed registry-match-or-deterministic-fallback rule defeats its own session-ownership check: when the same truncated plan subdomain is registered to another session, rejecting that row and synthesizing the identical URL still opens the other session's page. It also accepts an empty registry URL as the matched page, although the clients only specify a `null` failure state. Non-plan hosted rows likewise become clickable links with empty hrefs on a box without a public base. **Evidence:** spec lines 110–116, 314–319; `src/shared/planMode.mjs:49–69` truncates the session slug and constructs the fallback from that same slug; `src/server/servePage.mjs:212–219` explicitly returns `url: ""` without a base; `src/renderer/artifacts.ts:240–243` documents the collision concern. **Fix:** distinguish absent registration from an ownership collision; a collision must yield `pageUrl:null`, never fallback. Normalize missing/empty/unusable URLs to null for plans, and omit unavailable hosted links with explicit degraded feedback (or specify a disabled row with a reason). Pin collision, empty-base registry match, and ordinary hosted-page empty-URL cases in node and consumer tests.

2. **BLOCKING — Desktop migration / Files: a typed consumer is omitted.** Replacing `Artifact` with the new wire type removes `key` and `expiresAt` and requires the new fields, but the migration does not include the existing preview test fixture. Following the declared file list leaves typecheck broken. The retained day-grouping tests also need their shared fixture migrated, rather than simply deleting the other cases. **Evidence:** `src/renderer/ArtifactPreview.test.tsx:13–26` declares a typed `Artifact` literal with the removed fields; `src/renderer/artifacts.test.ts:49–67` has the same old shape; `tsconfig.web.json:18` includes renderer tests in typechecking. Spec desktop table at lines 218–227 and Files at 1113–1118 omit `ArtifactPreview.test.tsx`. **Fix:** add that test file to WS07 ownership/migration, update both fixture builders to the wire shape, and explicitly retain the preview action tests and day-grouping tests under the normal typecheck gate.

3. **BLOCKING — Mount M-04-2: receipt no longer matches the canonical mount, and retry can be dead.** The receipt still says to replace the Open terminal row in place, inside its existing Section, with a component that itself emits Sections. The master now explicitly requires sibling Sections. In addition, the receipt renders the mode component when selection exists even if the optional retry callback is absent; a failed catalog then displays a Try again button whose handler does nothing. **Evidence:** spec line 1194; master `00-master.md:520`; `mobile/native/MantaUI/ChatOverflowSheet.swift:100–112`; `SessionModeMenu.swift:39–68` emits Mode/AI CLI Sections and a visible retry button calling `onRetry()`. **Fix:** copy the master's sibling-Section placement into the receipt and reconcile WS04's provider row. Require a real retry callback whenever the retry-bearing component is mounted, or explicitly disable/hide retry with a reason when unavailable. Preserve the legacy and read-only behavior; add failed-catalog/missing-callback verification.

4. **SHOULD — Server-first memoization: the key omits response-affecting inputs.** The key can reuse stale core data after a public-base change, a page republish with the same expiry, an outbox sidecar change, or content changes within the same final transcript part. Recomputing expiry state does not fix a cached stale expiry timestamp. A failed optional source and a successfully read empty source can also have the same signature, so `degraded` must not be inherited blindly from a cache hit. The 30-second TTL bounds these problems, but the promised immediate invalidation is incomplete. **Evidence:** spec lines 164–173; `src/server/servePage.mjs:212–219` derives URL from the current base and returns `createdAt`; `src/server/outbox.mjs:111–129` reads expiry/message ownership separately from file mtime; `src/server/opencode.mjs:511–519` returns mutable mapped message content. **Fix:** include base URL and all derivation-relevant page/outbox fields in the signature, derive current degraded status per request, and specify the deliberate maximum staleness for in-place transcript updates (or invalidate on a content revision). Add fake-clock tests for source failure/recovery, base changes, expiry sidecar changes, and an unchanged-id/part-count text update. Ensure cache age means age since derivation, not age since last hit.

5. **NIT — Superseded scope and registration statements remain normative-looking.** The header says no server file is edited; the testing section says no node tests and unaffected npm checks; the response appendix still describes `artifacts.list` and WS11-owned capability registration before later correcting it. **Evidence:** spec lines 9–10, 992–993, and the server-first response bullets beginning “Wire compat” / “Ledger”. These conflict with the actual server-first section and D25. **Fix:** remove or mark the obsolete statements as historical, and make the current capability id, wave-B registration, and verification requirements consistent throughout.
