## Findings

1. **BLOCKING — Mounts applied / WS04 mode rows.** The receiver still implements the superseded launcher API. It declares `[SessionLauncher]` and calls `SessionModeRows(current:launchers:onSelect:)`, but WS04 now consumes WS10's `[AvailableLauncher]` and requires `catalog` and `onRetry`; it also supplies optional `mode` and the additional overflow parameters. Independent implementation of these contracts will not compile, and omitting the catalog/retry would remove the specified failed-discovery recovery. **Evidence:** `07-artifacts-cards.md:879`; `04-sessions.md:229-235,1312,1315`; master D21 assigns discovery to WS10. **Fix:** replace this receipt with M-04-2 verbatim in substance: optional mode, `[AvailableLauncher]`, `SessionLauncherCatalog`, selection and retry closures, and the full `SessionModeRows` initializer. Pin sensible defaults for legacy callers and unwrap the mode before rendering. Include WS10 in prerequisites.

2. **BLOCKING — M-07-1 / WS02 mount receipt.** WS07 now accepts a `composer` instance and owns attachment rejection reporting inside the card, whereas WS02 still constructs the card with the removed `onAttach` callback and reports every rejection as “Already attached.” This is both an initializer mismatch and a conflicting error owner. **Evidence:** `07-artifacts-cards.md:288-295,860`; `02-chat-cards-queue.md:800`. The current card has neither parameter (`mobile/native/MantaUI/SessionResourceCards.swift:370-372`), so there is no existing compatibility overload to reconcile the two. **Fix:** synchronize WS02's receipt to M-07-1: pass `composer`, remove `onAttach` and the external attachment hint, and preserve the jump-on-dismiss wiring. State that the card closes only after successful attachment.

3. **SHOULD — F6, temporary-file cleanup contract.** The new machine cannot implement all its promised cleanup effects with the declared state/signatures. Transitioning from `.presenting(..., fileURL:)` to `.saved(opID:)` loses the URL that must be deleted later; `savedTimerFired` returns no effect; and a mismatched `presentationFinished(token:opID:completed:)` has no URL from which to construct `.deleteTemp`. **Evidence:** `07-artifacts-cards.md:407-430,446-456,475-476`. **Fix:** retain the staged URL through the saved phase (or a separate operation-owned field), return cleanup effects from timer completion, and explicitly assign stale-presentation cleanup to a callback carrying its captured URL or an operation registry. Add tests asserting the actual temp file is removed after save success/timer, cancellation, share completion, and a stale callback—not only that the next notice survives.

4. **SHOULD — F4 / M-07-1, attachment visibility in read-only jobs.** The claim that checking `composer != nil` hides attachment actions on read-only surfaces does not hold for this mount: M-07-1 always passes the controller, while WS03 retains that controller and flips `acceptsInput` to false. Thus a read-only job still offers Attach, downloads/uploads a fresh copy, and only then rejects it. The failure is visible, so this is not classified as a blocking dead control, but it is misleading and unnecessary work. **Evidence:** `07-artifacts-cards.md:288-295,860`; `03-composer.md:483-489,599`; `02-chat-cards-queue.md:433-441` (composer view replaced, resources retained). **Fix:** gate the action on the controller's current `acceptsInput` as well as presence/project, or pass nil when mutations are forbidden. Recheck before starting upload and keep rejection reporting for policy changes during an in-flight operation. Add a read-only-job artifact-card case.

5. **NIT — Mounts applied IDs and cross-check claim.** The incoming ledger still calls the display toggle “WS01 M4” and read-only guard “WS02 M3,” and references WS04's obsolete `(a)/(b)` labels. Their canonical outgoing IDs are now M-01-5, M-02-2, M-04-1 and M-04-2. Rename placement also differs (before Compact here, before Fork in WS04); optional/defaulted versus required rename closure should be reconciled explicitly. **Evidence:** `07-artifacts-cards.md:876-884`; `01-transcript.md:1375`; `02-chat-cards-queue.md:779`; `04-sessions.md:1311-1312`. **Fix:** use the canonical IDs on both sides, agree placement and defaulted closure behavior, and update the “Cross-check” paragraph so the ledger is traceable without guessing.
