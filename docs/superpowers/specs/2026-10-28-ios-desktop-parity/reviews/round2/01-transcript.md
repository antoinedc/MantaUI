## Findings

1. **BLOCKING — Mount requests M-01-1 through M-01-4 / WS02 F11 and Mounts applied.** The receiver's contract still describes the pre-revision implementation. WS01 requires `truncationByMessageID`, but WS02 explicitly drops that property. WS02 also accesses `TranscriptMediaStore.shared.entries[sessionId]` and `$entries`, while WS01 now provides `entries(for:)` and `$sessions`. Implementing both specifications literally fails compilation. Its suppression rule also reintroduces round-1 #7 by hiding a warning merely because its message is loaded. **Evidence:** `01-transcript.md:1215-1226` and its M-01-1–M-01-4 table; `02-chat-cards-queue.md:649-661,793-797`; current `mobile/native/MantaUI/ChatModels.swift:189-191` excludes incomplete messages, so loaded does not mean a warning is rendered. **Concrete fix:** update the WS02 receiving ledger and F11 together: retain a bounded per-message truncation map, use WS01's current store members and conversions, subscribe/remap on the specified changes, and suppress only using `footerTruncationMessageIDs`. Reconcile WS02's `presentedMessages` focus slice with the message list used for both canonical mapping and `liveMediaTail`, so the same owner cannot appear in both segments. Include an integration test compiling the actual provider/consumer signatures and exercising an incomplete truncation snapshot.

2. **SHOULD — F4 mapper emission predicates.** The new live fallback is used to populate a footer, but is absent from the conditions that decide whether that footer exists. A completed, non-final assistant message with no canonical finish/usage and only a live truncation gets no footer. Conversely, the unconditional last-message-with-prose condition can create a reply footer while `running` is true even though `TranscriptTurns.info` deliberately suppressed its entry. **Evidence:** `01-transcript.md`, F4's three mapper emission conditions and the new canonical-or-live paragraph; `src/shared/opencodeV2.mjs:276-289` emits `step-finish` only with usage; `src/renderer/chatUtils.ts:3137-3144` implements the running-turn suppression. **Concrete fix:** compute the effective truncation before deciding emission and use it in the predicate. Explicitly gate the prose/reply-actions fallback on a finished turn, separately from mid-turn warning-only rows. Add tests for live-only truncation on a non-final message and for a completed last step with prose while the session remains running.

3. **SHOULD — Package manifest / Client members portability.** The new pure file is specified to import only Foundation, yet it now owns a `URLRequest` builder and SHA-256 cache-key implementation. `URLRequest` requires FoundationNetworking on Linux; Foundation does not provide SHA-256. The current manifest has no crypto dependency, and the spec supplies no portable hashing implementation/dependency decision. **Evidence:** `01-transcript.md`, F1 Bounded staging and Client members (`TranscriptPeekRequest.make` in `TranscriptMediaModel.swift`); `mobile/native/Package.swift:31-65` contains no package dependencies; `mobile/native/MantaUI/MantaError.swift:3-5` already documents the networking split. **Concrete fix:** pin the portable arrangement: conditional FoundationNetworking import for request-building tests (and amend the Foundation-only wording), plus an explicit cross-platform hashing choice, or keep request/hash work in the app-only layer and test a Foundation-only key-input representation in the Linux package. Update the manifest/test ownership accordingly rather than leaving the implementer to introduce an undeclared dependency.

4. **NIT — Mounts received / WS07 receiver ledger.** The underlying appliers and display-toggle behaviour agree, and no duplicate `peekFileSize` or `downloadPeekFile` declaration was found in WS02–WS10. However, references still use retired mount IDs and filenames: WS01 calls the highlight request “WS02 M1” instead of M-02-1; WS07 calls the display toggle “WS01 M4” and locates the preference in `TranscriptReasoning.swift`, rather than M-01-5 and `TranscriptDisplayOptions.swift`. **Evidence:** `02-chat-cards-queue.md:778`; `07-artifacts-cards.md:876`; WS01 Mounts received and Files tables. **Concrete fix:** synchronize those ledger labels/source filenames so integration follows one identifiable request per mount.
