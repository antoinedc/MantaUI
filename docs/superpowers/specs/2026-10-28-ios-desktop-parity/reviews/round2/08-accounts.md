## Findings

1. **BLOCKING — Shared sign-in machinery, Attempt-scoped teardown.** Late-start teardown is not attempt-scoped for F3 Codex. Cancel while `providerAuthStart` is outstanding can retire an attempt before it has recorded resources; a new Connect can start a second wait. If the first reply then arrives, the prescribed one-off teardown sends `oauth-cancel {id:"openai"}` and deletes the *second* wait. Its next status poll fails despite the user approving the current code. A client UUID does not scope this server operation. **Evidence:** `08-accounts.md:250–280` prescribes provider-ID cancellation and immediate teardown of late start replies; `src/server/rpc.mjs:138–155` defines one callback slot per provider, `:418–423` starts that slot before returning the start reply, and `:2262–2266` unconditionally deletes the slot by provider ID. **Fix:** explicitly serialize same-provider start/retirement across controller dismissal and recreation until an outstanding start and its cleanup finish; never run an old attempt's provider-wide cancellation after a newer attempt owns that provider. Keep unique-key Claude and seat/flow cleanup separate. Specify an async test: start A outstanding → Cancel → request B → late A reply; B must either remain deferred until A cleanup completes or remain unaffected by that cleanup. This can be solved client-side without expanding D7.

2. **SHOULD — F4 Write reconciliation.** The new pure function cannot implement its stated distinction between “pre-write state” and a “third state”: its inputs are only `reply`, `readBack`, and the desired `expect`, with no original endpoint snapshot. For an existing endpoint toggle, two different original selections can produce exactly those same inputs but require rejected versus partial outcomes. **Evidence:** `08-accounts.md:690–707` gives the signature and both branches; `src/server/providers.mjs:528–564` is the non-atomic write being classified. **Fix:** add an explicit `before: ProviderEndpoint?` input (captured before the write), or replace the distinction with an outcome that does not require unavailable information. Update tests with identical reply/read-back/expect and different pre-write states. Also make F4's local outcome explanations defer to the shared classifier: a thrown write with matching read-back is confirmed, not invariably partial.

3. **SHOULD — Mount requests / Mounts applied tables.** The cross-spec ledgers are still out of sync, although the essential observer is now described in WS09's implementation section. WS08 calls M-08-1 a mandatory mount; WS09's received table says “None” and explicitly classifies that request as not a mount. WS08 accepts the old `M7` price link, while WS09 now calls it `M-09-6` and defaults it to not applied unless accepted. WS08 leaves M-08-2 optional/open while WS02 has explicitly declined it. These inconsistencies can make the D18 integration checklist omit or misidentify work. **Evidence:** `08-accounts.md:991–1012`; `09-models-usage.md:1232–1245`; `02-chat-cards-queue.md:803` (the optional WS08 row is declined). **Fix:** list M-08-1 as received/applied by WS09, with its notification test; change WS08's acceptance to the canonical M-09-6 and mirror acceptance in WS09; mark M-08-2 declined in WS08. The Reconnect initializer contract and WS10 `opencodeRestart() -> OkResult` client contract agree; no duplicate WS08 client member was found in the other specs.

VERDICT: CHANGES REQUIRED
