## Findings

1. **BLOCKING — F1 Bounded staging, cache key input.** The revised data-URL key uses only MIME, encoded length and the first 64 base64 characters. Different attachments with the same prefix and length therefore share a cache filename and in-flight task. Opening the second attachment can display/share the first file. SHA-256 cannot repair a collision already introduced by truncating its input. **Evidence:** `01-transcript.md:355-358,366,373`; `src/shared/opencodeV2.mjs:293-310` permits arbitrary inline file data. A local base64 probe of `b'A'*48+b'first-file'` and `b'A'*48+b'other-file'` confirmed different payloads with identical encoded lengths and first 64 characters. **Concrete fix:** include the entire base64 payload in the canonical key input, or compute a full-content digest in the app-only hashing layer. Keep the portable test seam, but add two equal-length, equal-prefix, different-suffix sources and require different keys and independent staged bytes/coalescing.

2. **SHOULD — F1 liveMediaTail / M-01-2, historical versus current media.** The new `isLiveWindow` expression does not detect historical focus: WS02's focus slice is a suffix ending at the latest loaded message, so its last ID still equals `messages.last`. Also, an absent owner can be an old, already-settled message outside the 30-message window, not just a new step awaiting refetch. Since the live store retains session entries, those old media can be appended again at the tail. **Evidence:** `01-transcript.md:419-435`; `02-chat-cards-queue.md` F10 step 3 (`presentedMessages = Array(messages[index...])`); `mobile/native/MantaUI/ChatSessionStore.swift:253,343` establishes the bounded transcript window. **Concrete fix:** define eligibility using active-turn/pending ownership or retire live entries once canonical data has absorbed them; use explicit focus state if historical focus must suppress tail media. Synchronize any signature change through the canonical ledger and WS02 receipt. Test a settled media owner older than the loaded window and a focused suffix whose last ID equals the full list's last ID: neither should resurrect unrelated historical media at the tail.

3. **NIT — F4 single-truncation rationale.** The binding latest-only fallback decision is internally consistent, but “Only the latest warning can lack a canonical record” is not established by the wire. Missing usage can affect an older message too; refetching does not create its missing `step-finish` part. **Evidence:** `01-transcript.md:880-883`; `src/shared/opencodeV2.mjs:276-289` conditionally emits that part only when tokens exist, whereas `src/server/streamInterp.mjs:885-893` emits a live warning independently. **Concrete fix:** retain the agreed single-value contract, but document that older warnings without sufficient canonical finish metadata may disappear after a newer warning/reload. Narrow the absolute persistence acceptance accordingly rather than claiming a server guarantee that does not exist.
