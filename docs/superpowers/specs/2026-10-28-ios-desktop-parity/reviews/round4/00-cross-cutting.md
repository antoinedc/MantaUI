Confirmation review of the round-3 fixes and subsequent changed seams, against the canonical ledger/registry, provider and receiver contracts, existing Swift receiving scopes and package manifest. No implementation build or test run is claimed. Spec paths below are relative to this spec directory.

## Findings

1. **BLOCKING — WS01 F1 / M-01-1…3: the new media lifecycle requirement is not represented in the integrated contract.**
   - **Problem:** the new pure-tail predicate requires `TranscriptMediaEntry.turnStartedAt`, which the prescribed entry does not declare. Its session-current-turn cutoff is also unavailable through the pinned helper inputs. Retirement additionally requires canonical snapshot/settlement delivery to the media store, but the store only subscribes to media frames and WS02's receipts only read its entries/observe changes. Following the declarations literally cannot compile the new member access; independently inventing the missing lifecycle plumbing in either worker does not satisfy the binding cross-owner contract.
   - **Evidence:** `01-transcript.md:178-210,327-333,424-436`; `00-master.md:377-379` (M-01-1…3); `02-chat-cards-queue.md:899-901` (receipts). Actual `src/server/media.mjs:308-321,351-363` publishes media identity/geometry but no turn boundary or canonical snapshot. The pure helper receives `presentedMessages`, which can be a focus suffix, not the complete session history.
   - **Concrete fix:** pin the complete lifecycle contract: entry field/type/units and assignment, authoritative current-turn identity/cutoff, and snapshot/settlement reconciliation API. Specify its delivery from WS02, including turns without a new user message and focused slices that exclude the turn's start. Update provider, canonical ledger/registry and receiver receipts together. Require a reducer-to-store-to-tail integration test using those actual inputs rather than fabricated entries. An alternative fully wired eligibility mechanism is acceptable; an undeclared timestamp is not.

2. **SHOULD — WS01 F1 retirement: owner presence is not proof that canonical data replaces the live card.**
   - **Problem:** a snapshot containing begin-owner A but no successful show causes the new rule to drop the live placeholder. Canonical reconstruction explicitly drops unshown begins, so nothing replaces it. Blanket post-turn retirement similarly discards the live failure state. This is a display/lifecycle regression, classified below BLOCKING under this round's build-breaking/dead-control threshold.
   - **Evidence:** `01-transcript.md:289-296` retains pending/failed live entries and drops unshown canonical begins; `:433-436` retires by owner presence or settlement. The server assigns the begin and show their respective calling message IDs (`src/server/media.mjs:308-321,351-363`), so the begin owner can exist before the show is reconstructable.
   - **Concrete fix:** retire ready entries only when canonical reconstruction supplies the same media identity. Define pending/failed retention separately, while keeping old retained entries out of unrelated turn tails. Test begin A → snapshot containing A without show; failure → post-turn refetch; ready → matching canonical replacement.
