## Findings

1. **BLOCKING — F1 liveMediaTail, current-turn state is undeclared and unpopulated.** The new predicate reads `TranscriptMediaEntry.turnStartedAt`, but that member is absent from the entry declaration. No current-turn start is supplied to the pure helper or reducer, and the live store still binds only `kind == "media"`, whose payload contains no turn-start field. The retirement policy additionally needs canonical snapshots/post-turn-refetch events, but no store method or receiving mount delivers them. **Evidence:** `01-transcript.md:178-210` (entry/frame/reducer), `:327-333` (store API), `:424-436` (new requirements), M-01-1…3; actual media payload construction in `src/server/media.mjs:310-321,351-363`. **Concrete fix:** define the entry field, units and assignment rule plus the source of current-turn identity/start (including non-user-triggered turns). Pin the snapshot/settlement input method and its WS02 mount, updating ledger and receipt together if required. Alternatively remove the timestamp predicate and specify a fully wired current-turn eligibility mechanism. Test the real reducer/store-to-tail path, not a manually fabricated entry alone.

2. **BLOCKING — F1 retirement treats owner presence as canonical absorption.** Dropping live entries as soon as a snapshot contains their owner deletes pending/failed media that the canonical mapper cannot reconstruct. A begin's message A can settle and be present while its show in B is still pending; `canonicalEntries` deliberately drops a begin with no show. The new retirement rule therefore removes the only placeholder. Dropping all entries after the turn's refetch likewise removes a failed/orphan placeholder despite the promised visible failure state. **Evidence:** `01-transcript.md:433-436`; F1 Owner policy/Reconciliation step 3 explicitly drops unshown begins from canonical data and preserves live failures; `src/server/media.mjs:308-321` associates begin with A, while `:351-363` associates show with its calling message. **Concrete fix:** retire a ready live entry only when a canonical entry with the same media identity actually replaces it. Give pending/failed entries an explicit retention and placement policy rather than deleting them based on owner-message presence or blanket settlement. Test begin A → snapshot containing A but no show → placeholder retained; fail → post-turn refetch → failure remains visible; ready → matching canonical entry → live entry safely retired. Keep old retained failures out of unrelated current-turn tails.

3. **NIT — F4 Acceptance still promises unconditional reload persistence.** The new trade-off paragraph is correct, but the acceptance checkbox still says the warning “is still there after reopening the chat” without qualification. **Evidence:** `01-transcript.md:895-899` versus `:1050-1051`; `src/shared/opencodeV2.mjs:276-289` conditionally emits canonical step-finish metadata. **Concrete fix:** qualify that checkbox with “when canonical finish metadata is available,” matching the revised paragraph.
